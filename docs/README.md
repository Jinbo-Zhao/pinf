# Documentation

This folder holds the source of the documentation site, which is built with
[Sphinx](https://www.sphinx-doc.org/) and hosted on
[Read the Docs](https://docs.readthedocs.io/en/stable/tutorial/index.html).
This file is for maintainers; it is not part of the site.

## Build and preview locally

From the repository root:

```bash
pip install -e ".[docs]"
sphinx-build -b html docs/source docs/build/html
python -m http.server 8000 -d docs/build/html
```

Open <http://localhost:8000>. Re-run `sphinx-build` after every change and
refresh the page. Read the Docs builds with warnings treated as errors, so check
locally with `-W` before pushing:

```bash
sphinx-build -W -b html docs/source docs/build/html
```

If a page looks stale, delete `docs/build/` and build again.

## Where the content lives

Most of the text is **not** in this folder. The pages in `docs/source/` are thin
wrappers that pull content in from elsewhere, so each piece of text has a single
source.

| Site section | Source of the content | Edit here |
|---|---|---|
| Home page intro, Installation, Main Elements, Quick Start, Solvers, Streamlit GUI, Testing, References | The matching section of the top-level [`README.md`](../README.md), between `<!-- start: NAME -->` and `<!-- end: NAME -->` | `README.md` |
| Page titles, sidebar navigation and order | [`source/index.md`](source/index.md) and the `source/*.md` wrappers | `docs/source/` |
| Tutorials | The notebooks in [`notebook/`](../notebook/), rendered with their saved outputs (they are **not** executed during the build) | Re-run and save the notebook in Jupyter |
| API Reference | Docstrings in [`src/plausible_inference/`](../src/plausible_inference/), generated by sphinx-autoapi | The docstrings |
| Theme, extensions, project name, version | [`source/conf.py`](source/conf.py) | `conf.py` |
| Read the Docs build settings (OS, Python version, install command) | [`.readthedocs.yaml`](../.readthedocs.yaml) | `.readthedocs.yaml` |
| Docs dependencies | The `docs` extra in [`pyproject.toml`](../pyproject.toml) | `pyproject.toml` |

Generated, git-ignored paths (never edit them):

- `docs/build/`: build output.
- `docs/source/tutorials/`: copies of the notebooks, made by `conf.py` on every build.
- `docs/source/autoapi/`: API pages, generated during the build.

Anything in `docs/` outside `docs/source/` (such as this file) is not part of the site.

## Common edits

### Change text that comes from the README

Edit the section in the top-level `README.md`. The change shows up on both
GitHub and the docs site.

Keep the `<!-- start: NAME -->` / `<!-- end: NAME -->` comments intact. They are
invisible on GitHub, but the docs pages use them to pick out each section. If
an end marker is removed or renamed, the build still succeeds but the page
silently includes everything up to the end of the README, so check the page
after editing near a marker.

Avoid in-page links such as `[Solvers](#solvers)` inside an included section:
on the docs site that section sits on a different page and the link breaks.

### Write documentation that is not in the README

Create a Markdown file in `docs/source/` (for example `docs/source/faq.md`) that
starts with a `# Title` heading, then add its name without the extension to a
`toctree` in `index.md` (see below). Pages use
[MyST Markdown](https://myst-parser.readthedocs.io/), so plain Markdown works
and Sphinx directives are written as fenced blocks, for example:

````markdown
```{note}
Gurobi requires a license.
```
````

Math is written as `$...$` inline or `$$...$$` as a block.

### Pull a new README section into the docs

1. In `README.md`, wrap the section body with markers:

   ```markdown
   ## My Section
   <!-- start: my-section -->
   ...content...
   <!-- end: my-section -->
   ```

2. Create `docs/source/my-section.md`:

   ````markdown
   # My Section

   ```{include} ../../README.md
   :start-after: <!-- start: my-section -->
   :end-before: <!-- end: my-section -->
   ```
   ````

3. Add `my-section` to a `toctree` in `index.md`.

### Update the API reference

Edit the docstrings in `src/plausible_inference/`. Google and NumPy styles both
render. Docstrings are parsed as reStructuredText, which has two common pitfalls:

- `|x|` is read as a substitution and breaks the build; wrap math in double
  backticks, e.g. ``` ``|x_i - x_j|`` ```.
- A bulleted list needs a blank line before and after it.

A new module is picked up automatically. A new sub-package needs an
`__init__.py`, or autoapi cannot resolve its imports.

### Add or update a tutorial

Save the notebook with its outputs in `notebook/`, then add
`tutorials/<notebook name without .ipynb>` to the Tutorials `toctree` in
`index.md`. Read the Docs has no Gurobi or SCIP, so notebooks are never executed
there: what you see on the site is exactly what was saved in the notebook.

## Change the structure

### Reorder, add or remove pages

The sidebar is defined by the `toctree` blocks in [`source/index.md`](source/index.md).
Each block is one sidebar section; its `:caption:` is the heading and each line
is a page (the file name relative to `docs/source/`, without extension):

````markdown
```{toctree}
:maxdepth: 2
:caption: User Guide

installation
concepts
```
````

- **Reorder pages:** reorder the lines.
- **Add a section:** add another `toctree` block with its own `:caption:`.
- **Remove a page:** delete its line and its file. A page that exists but is not
  in any `toctree` triggers `document isn't included in any toctree`, which fails
  the build with `-W` and therefore on Read the Docs.
- **Nest pages:** put a `toctree` inside a page other than `index.md`; the pages
  it lists appear under that page in the sidebar.

### Change the look or Sphinx settings

Edit [`source/conf.py`](source/conf.py): `html_theme` for the theme,
`extensions` for Sphinx extensions, `autoapi_*` options for the API reference,
and `project` / `release` for the name and version. A new extension must also be
added to the `docs` extra in `pyproject.toml`, or Read the Docs cannot install it.
Static files such as a logo or favicon go in `source/_static/`. Style tweaks go
in [`source/_static/custom.css`](source/_static/custom.css), which `conf.py`
loads through `html_css_files`; it currently makes table cells wrap instead of
forcing horizontal scrolling.

## Publishing

Read the Docs rebuilds the site automatically on every push to the repository
(and on pull requests, if previews are enabled in the project settings). The
build log is on the project's Builds page at readthedocs.org; a failed build
leaves the previous version online.
